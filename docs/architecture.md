# 架构与决策

## 当前范围

目标是让后续素材进入一条已验证的交付链路：占位互动 → 版本化契约 → 服务端处理 → 第一方事件持久化 → 发布制品与回滚。时序点击和滑动收集是通用技术探针，不代表未读取 Keynote 中的玩法已实现，也不定义正式活动的会员、抽奖或兑奖规则。

## 最小可部署边界

- `web`：React + TypeScript + Vite，静态资源自行托管；移动端、键盘与减少动态效果均是基础交互要求。
- `api`：Node.js 24 + Fastify，一个模块化服务；活动、事件、身份与外部适配器在代码中分离。
- `contracts`：共享运行时 schema、TypeScript 类型和公开活动/资源清单。服务端进行校验，前端类型不能代替不可信输入检查。
- PostgreSQL：参与记录与事件去重的持久事实。当前没有 Redis、消息队列、微服务、CMS 或通用活动 DSL。
- 同源入口：本地由 Vite、容器由 Nginx 将 `/api` 转给 API。后续由客户指定的国内 CDN/网关承担 TLS、缓存和入口防护。

页面首屏不依赖境外字体或第三方脚本 CDN。现有部署文件用于本地验证，未采购或创建任何云资源。

## 状态和信任来源

交互状态由浏览器管理；服务端参与记录由数据库确认；真实会员、订单、权益只能由未来获授权的外部接口确认。参与结果中的 `recorded` 只表示本次技术探针的参与已被记录。

外部适配器固定为测试模式并显式返回 `providerMode: mock`。生产环境启动拒绝 mock；这是一道尚未接入真实提供方的明确门禁，不能通过改标签将模拟接口视为真实联调。

服务端通过匿名 HttpOnly Cookie 识别会话，对写请求校验来源并限制请求体和访问频率。前端不能自行指定可信业务身份。开发进程可以临时生成会话签名密钥；跨重启、多实例或真实部署必须通过安全环境配置注入稳定的 `SESSION_SECRET`，不可提交到仓库。

## 事件契约

客户端事件必须显式获得验证台中的可选采集同意。拒绝后清空尚未发送的客户端队列；已经送达服务端的记录不会因为本地清队列而被删除，真实删除请求需要单独的受控流程。

事件只允许约定字段和属性白名单，不接受任意 DOM、URL、邮箱、手机号或用户输入。`eventId` 用于重复投递去重；客户端时间与接收时间分开。重试保留相同 ID。相同 ID、不同内容是冲突，不能静默覆盖。

浏览器上报是有限队列的尽力投递。只有明确接收确认才能作为队列出队依据；`sendBeacon` 返回值不能证明数据库持久化。异常退出仍可能丢失事件。参与成功等关键指标应以服务端业务事实为准，并能够与事件对账。

采集入口是一方域名不意味着可以绕过客户的数据政策。正式运行前必须确认采集目的、允许属性、保留时长、删除方式和访问权限。事件落点可适配客户现有分析系统，不将调试日志当作分析平台。

## 幂等与数据库

同一匿名会话、活动和幂等键应返回同一参与结果；数据库唯一约束是最终防线。幂等键只能防止同一个操作的重复处理，不能替代未来的资格、次数、反作弊或奖品库存规则。

迁移使用带校验记录、事务及 advisory lock 的显式 SQL。首期迁移可重复执行；任意更改已应用 SQL 应失败，而非静默改写历史。正式演进采用新迁移文件。

## 发布契约

同一版本应绑定页面、公开活动配置、资源清单和 API 制品。Vite 内容哈希资源长期缓存，HTML 不缓存；未知资源返回 404，避免用 SPA HTML 掩盖缺失文件。构建时保留提交与 release 标识，发布时晋级相同制品。

基础镜像使用经过实际拉取校验的 manifest digest 固定，标签仅便于识别版本；更新时重新验证并一起更新引用。正式发布还应记录最终应用镜像 digest、依赖审查结果及制品标识。数据库变更需向后兼容，代码回滚不等于数据回滚。

## 延后的决定

具体 Canvas/PixiJS/Rive 方案取决于可读取的创意演示和真机探针；真实会员/Apple 适配取决于沙箱、权限及协议；容量、分析存储和 CDN 采购取决于流量与客户部署约束。这里没有替这些外部条件作出假设。
